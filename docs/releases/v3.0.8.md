# Bots4Velo v3.0.8

This patch fixes rental BOT authentication loops reported in Issue #3.  A
rental BOT could receive both AuthMe login and registration prompts on one
connection.  The previous state tracked `loginSent` and `registerSent`
independently, so the bot could submit `/login` and then `/register` (or the
reverse) before AuthMe had confirmed either command.  AuthMe then kept the
connection pending and the rental server-switch request was rejected with
`AUTHENTICATION_PENDING`.

## Changes

- Select one authentication command (`LOGIN` or `REGISTER`) per connection.
- Ignore opposite-type chat and structured AuthMeUI prompts after a command
  has been selected, while recording `AUTH_PROMPT_IGNORED` for diagnosis.
- Preserve the first prompt during the AuthMeUI detection grace period instead
  of replacing it when another prompt arrives.
- Release the selection when command submission fails so a later prompt can be
  retried with the correct command.
- Clear the selection with the rest of the authentication state on reconnect.
- Keep command submission separate from confirmed authentication; server
  switching remains gated on the explicit AuthMe success signal.

Jail BOT authentication behavior is unchanged.  The fix is confined to the
per-`BotSession` command-selection state and applies independently to each
rental BOT connection.
